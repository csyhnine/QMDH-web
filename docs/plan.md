## 1. Project Goal

QMDH-web 为设计院内部提供 AI 设计生产平台，统一接入图像、视频与对话能力，保留任务、资产、用量和失败记录。当前处于 **1.0 生产内测与稳定化** 阶段，优先改善可靠性、历史查询、运维和交接质量。

## 2. Current Capabilities

- React + Vite + TypeScript 前端，FastAPI + SQLAlchemy 后端；生产使用 Docker Compose、PostgreSQL 与 Redis worker。
- 图像生成/编辑/放大、视频生成、画布、普通 Chat、模板、资产与账号管理已有代码入口和实际供应商适配。
- 数据库账号/会话、角色权限、provider key 加密、用量账本与管理看板已有实现。Studio 生成历史按账号归属，项目是个人任务容器。
- CAD 图纸提取已部署；2026-10-16 用户新授权后接入官方 Linux ODA 27.9，生产支持 DWG 自动转 DXF 后解析，旧图不重跑。
- 后端已有 pytest 测试集与 Alembic 迁移；前端已有 Vite 构建和部分 lint。本地已新增 `.github` CI 配置与统一检查命令，未提交/未在 GitHub 运行；完整 TypeScript 检查仍有已有错误，新增错误由基线检查阻止。
- Agent/harness 等代码存在，不代表助手产品已开放；生产助手 UI 按现有交接保持关闭。

代码能力、工作区修改和生产发布应分别核对。生产版本及运行镜像见 `handoff.md`、`continuity.md`；模型启用和价格等配置以生产数据库为准。

## 4. Success Criteria

- 用户可发起任务、查询状态、查看/复用资产；较老运行任务及历史记录不因列表限制失联。
- 身份、权限、用量与失败信息由服务端可信记录支撑。
- 部署保留业务库、媒体和配置，schema 与 Alembic 元数据一致。
- 新 agent 能区分已部署、已提交和本地未提交状态，不依赖聊天记录恢复项目事实。
- 有可重复的针对性验证，基线失败和新增回归明确区分。

## 5. Risks And Constraints

- 本地 Studio 两项改动尚未提交/部署，原访客样式、比较文档和临时脚本仍须隔离。
- 完整类型检查和部分扩大回归未全绿；不能把构建通过等同于所有检查通过。
- 生产负载、磁盘、模型配置是时点事实，旧测量不能直接用于当前容量判断。
- 启动仍有 `Base.metadata.create_all` 与兼容补列 `ensure_schema`；生产仍必须按 Alembic 运维流程核对，不可把启动成功当作迁移完成。
- 禁止更换 `QMDH_ENCRYPTION_KEY`，禁止 `docker compose down -v`，禁止提交密钥、本地数据库、存储和临时脚本。
- 不扩大到微服务、多租户或完整 Agent 平台；不改 CAD 布置算法，不恢复已暂缓事项。
