1. `docs/server-operations.md` 的 2026-10-19 记录说明，线上运行镜像来自额外发布源码与热修，服务器 Git HEAD 不能代表运行内容。该文档是历史记录，当前镜像仍待只读核对。

## 建议执行顺序

1. **只读核对现有服务器**：确认实际镜像 ID/发布清单、Compose 叠加文件、worker 数量、挂载、已应用迁移版本和构建开关。凭据值不输出、不改变；不提交任务、不运行维护 CLI、搜索重建或调度。目标使用既有文档的服务器，连接前确认本次授权范围。
2. **固定候选与差异**：以实际线上运行源码/镜像为基线，逐项说明本地修复增量及原有改动归属，生成最终源码/镜像清单和 SHA。不用旧 HEAD 或当前脏工作树直接覆盖线上。保持冻结项停止。
3. **隔离验收**：使用候选镜像、临时 PostgreSQL/Redis/媒体目录和无真实凭据配置，关闭外呼/自动任务；核对已有库结构升级、API 启动与关键页面/接口的发布烟测。使用已记录定向回归，避免全套/视频/GPU/付费调用。实际服务器私有备份与测试数据使用需单独明确边界。
4. **准备并校验回退**：发布前成套保存数据库与 env、媒体恢复链、原镜像、Compose/FRP 配置及发布清单；校验哈希及可恢复路径。回退以旧镜像和保留的新业务数据为原则，不自动 downgrade、不用旧 DB 覆盖发布后的新数据，不删除媒体/锁。
5. **最后批准生产切换**：候选与隔离结果可审阅后，列明发布范围、维护窗口和回滚触发条件，再切换 backend/3 worker/frontend。入口暂停与在途任务排空应按已有运维合同执行；不得强行重跑未知上游任务。发布后先做健康、版本、路由与静态包核对，不做真实生成验收。
