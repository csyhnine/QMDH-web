# 分院名称与管理数据隔离核验

管理界面与分院列表 API 统一使用规范名称“二分院”，去掉历史归属括注和页面解释。前端按规范 name 显示，即使旧 API 暂时返回历史 label，也不会再出现旧字眼。兼容历史数据的内部别名保留，现有项目、人员和归属不改写。

跨院访问条件保持为：个人账号在用、已获 company_management 授权且网站角色为 admin，才可以显式切换一/二/三分院。单有网站管理员角色不授予公司管理访问权。普通院管理账号只列出本院，在后端校验 unit 参数并限制查询的分院；猜测其他院项目或快照 ID 也无法读取。普通未获公司管理授权的员工不能访问管理数据。

本轮只读核对运行代码与本地基线，确认所有 18 个管理路由均经过公司管理权限校验，数据操作均经过分院作用域；账号权限只做聚合核对，没有修改授权或公开真实名单。当前仅一个在用且有公司管理授权的 admin 可以跨院，其余在用院管理账号不具备跨院角色。本次未新增或扩大任何账号权限。

22 项后端定向测试通过，覆盖三院 × designer/ops 管理账号组合、unit 参数伪造、项目推进/周文字、报表导出源、人员、归档/回收站、历史修订、周报快照、跨院更新/删除/立项/改派及撤权。20 项前端定向测试、13 目标类型诊断零新增、3 个完整 AppShell 合成 API 场景及 Vite 构建通过（仅原有大块提示）。浏览器验证规范名称、管理员切院请求作用域及院管理账号单院选项；生产未使用真实账号冒充或写入测试安排。
