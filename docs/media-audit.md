## 运行

在 backend 目录，使用项目虚拟环境。数据库 URL 必须已由运行环境注入 `QMDH_DATABASE_URL`；不要把连接密码写到命令行或文档。明确选择实际媒体根目录。

```powershell
.venv\Scripts\python.exe -m app.scripts.audit_generated_media --media-root <媒体根目录> --retention-days 30 --report <媒体目录之外的新报告路径.json>
```

容器/Linux 使用对应环境的 `python -m app.scripts.audit_generated_media`。当前镜像尚无此工具，本次不执行生产命令。省略 `--report` 时输出 JSON 到 stdout；报告文件必须不存在，不覆盖已有文件，报告目录需预先存在。报告包含内部文件路径和记录 ID，应当留在受控位置，不能提交业务报告到 Git。

SQLite 使用现有文件的 `mode=ro`，不存在的数据库直接失败；PostgreSQL 使用 REPEATABLE READ 和 READ ONLY 事务。反射实际默认 schema 的表，扫描所有字符串/文本/JSON 列（含归档、软删除行）。报告只列引用所在表、主键、列名，不输出字段内容、查询参数、提示词、连接字符串或 API key。当前业务表主键是记录标识。

## 报告与边界

- `referenced`：数据库仍引用，保留。URL 主机不用于排除引用，避免 CDN/历史域名产生漏判；`.bin` 与相同文件名的图片/视频扩展名互相保护，允许保守误保留。
- `expired_unreferenced`：文件 mtime 严格早于 30 天边界，未检出引用，仅为人工复核候选，不授权删除。
- `recent`：未过保留期且未检出引用。
- `references_not_in_local_inventory`：引用未进入本地清单；可能来自 OSS、其他文件类型、已缺失文件，不能直接判定业务链接失效。
- `skipped`：符号链接、越界目录及不支持的扩展名；不跟随链接，不审计这些内容。

仅盘点指定根目录的 `generated/` 图片/视频与 `.bin`，不处理上传附件、CAD 原图/转换文件、其他目录或远端 OSS。时间用 UTC，依据文件 mtime，不代表任务创建时间。数据库扫描采用批量读取，报告仍在内存汇总；大库须观察运行资源。本轮没有生产容量数据。

明文路径、嵌套 JSON、URL 编码、Windows 分隔符和常见 Markdown 引用可识别；加密/不透明值、非默认 schema、视图、特殊自定义字段类型不保证覆盖。并发上传/数据库修改、文件迁移和解析格式都可能影响快照，未来任何清理须重新审计并复核。任何扫描/访问异常使本次失败，不输出候选报告；工具不会据此执行清理。
